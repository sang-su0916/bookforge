# 이미지 정책 — 표지·본문·도비라의 문맥형 이미지 규칙

이 문서는 책의 분위기를 꾸미는 장식보다 독자의 이해를 우선한다. 실사풍 이미지, 편집 일러스트레이션, 저자 작성 SVG를 모두 사용할 수 있지만, 이미지마다 바로 앞뒤 문장과 연결되는 설명 목적이 있어야 한다. 관련 문장을 더 잘 이해하게 하지 못하는 이미지는 넣지 않는다.

## 무텍스트 절대 원칙

생성 이미지 안에 문자·숫자·로고·워터마크·간판 글자가 있으면 폐기하고 재생성한다. 프롬프트에 항상 다음을 포함한다:

```
no text, no lettering, no typography, no logo, no watermark, no signage
```

글자는 언제나 조판 레이어(테마)가 벡터로 얹는다. 생성 이미지 위에 코드로 글자를 후처리 합성하는 것도 금지 — 텍스트가 필요하면 프롬프트를 고쳐 재생성한다.

## 문맥 우선 선택 규칙

이미지를 넣기 전 다음 세 질문에 답한다.

1. 이 이미지는 본문의 어느 문장을 설명하는가?
2. 문장이나 SVG 도해보다 이미지가 독자에게 더 빨리 보여 주는 것은 무엇인가?
3. 독자가 최종 PDF 크기에서 3초 안에 알아야 하는 핵심은 무엇인가?

답이 분명하지 않으면 이미지를 넣지 않는다. 표지와 장 도비라의 분위기에 맞는다는 이유만으로 본문에 무관한 스톡 사진을 반복하지 않는다. 법률 조문·수치·기한·소유관계처럼 정확성이 중요한 내용은 이미지 생성 대신 저자 작성 SVG·표·타임라인으로 표현한다.

| 문장의 역할 | 권장 이미지 | 금지 또는 주의 |
|---|---|---|
| 상담·회의·서류 확인 같은 현실 장면 | 실사풍의 가상 장면 | 실제 기관·실존 인물·읽을 수 있는 문서·개인정보를 재현하지 않는다 |
| 사람의 선택·관계·절차의 흐름 | 편집 일러스트레이션 | 장식용 캐릭터만 넣지 말고 장면의 행동을 분명히 한다 |
| 숫자·법적 관계·단계·기한 비교 | 저자 작성 SVG·표·타임라인 | 가짜 문서 이미지나 알아보기 힘든 생성 글자로 대신하지 않는다 |
| 감정·이야기·장 전환 | 실사풍 또는 일관된 일러스트 | 앞뒤 장면과 다른 시대·장소·색감으로 독자를 혼란스럽게 하지 않는다 |

## 스타일별 아트 사용처

| 스타일 | 표지 | 본문 |
|---|---|---|
| practical | 벡터 타이포 또는 주제를 보여 주는 맥락형 일러스트 | 단계 설명은 SVG 우선, 장면 설명에는 실사풍·일러스트 선택 |
| insight | 벡터 회로 그래픽 또는 주제 관련 실사풍 장면 | 데이터·관계는 SVG, 전환부 이미지는 블루 단색조·저채도 선택 |
| academic | 타이포 전용 또는 개념을 돕는 절제된 일러스트 | 근거·수치·모형은 SVG·표로 정확하게 표현 |
| essay | 소형 정물 오브제 1점(선화·수채·콜라주 중 택1), 폭 = 지면의 38~52% | 원칙적으로 무이미지 |
| business | 벡터 기하 패턴 또는 사업 장면을 보여 주는 실사풍·일러스트 | 숫자·법적 흐름은 SVG·표, 무관한 장식 사진과 사진 반복은 금지 |
| magazine | 풀블리드 아트 필수 | 스프레드당 1컷 권장, 룩(조명·색온도) 이슈 단위 통일 |

## 배치 방법

- 표지 아트 파일명: `<book_dir>/assets/cover.png` (HTML 트랙은 자동 인식) / essay는 `assets/cover-art.png`
- 해상도: 풀블리드 표지는 긴 변 3,000px 이상, 본문 컷은 배치 폭 기준 300dpi
- 인물은 실존 인물 유사성 금지, 브랜드 로고·실제 제품 형태 모사 금지
- 본문 이미지는 설명하는 문단과 같은 면 또는 가까운 면에 배치하고, 이미지 단독 문단으로 쓴다. 캡션은 독자가 이해할 수 있는 평이한 문장으로 쓴다.
- 캡션에는 `AI 생성 이미지`, `AI 생성 일러스트`, `저자 작성 SVG` 또는 합법적으로 사용한 실제 사진의 출처를 표시한다. 생성 도구명·파일명·내부 경로·검수용 출처 ID는 표시하지 않는다.
- 생성 이미지가 실린 책은 판권면 또는 캡션에 생성 이미지 사용을 표기한다. 표기 문구 예: `AI 생성 이미지`.
- 생성 이미지 안의 가짜 문서 글자, 깨진 숫자, 무의미한 기호, 로고처럼 보이는 얼룩은 최종 PDF에서 발견 즉시 폐기하고 다시 만든다.

## 실사풍 이미지 프롬프트 계약

실사풍이라고 해서 특정 사진을 복제하지 않는다. 다음 요소를 장면별로 명시한다.

```text
[장면] 독자가 읽은 문장을 행동으로 보여 주는 가상의 장소와 인물
[핵심 행동] 누가 무엇을 확인·선택·대화하는지
[분위기] 책의 색감·시대·조명·카메라 거리
[안전 조건] fictional people, no identifiable person, no brand, no readable document
no text, no lettering, no typography, no logo, no watermark, no signage
```

서류를 검토하는 장면에서는 서류의 내용이 보이지 않게 하고, 독자는 손가락으로 항목을 확인하는 행동과 표정·관계만 이해하도록 한다. 법적 효력이나 실제 기관의 승인처럼 오해할 수 있는 장면은 만들지 않는다.

## 일러스트레이션 계약

일러스트는 한 권 안에서 색상·선 두께·인물 비율·명암을 유지한다. 복잡한 절차는 인물·오브젝트·방향만 단순하게 배치하고 이미지에 글자를 넣지 않는다. 설명해야 할 단계가 세 개 이상이면 일러스트 한 장에 억지로 담지 말고 SVG 순서도나 여러 장의 짧은 장면으로 나눈다. 이미지가 사실처럼 보일 수 있는 법령·서식·계약서·계좌 화면은 일러스트로 흉내 내지 않는다.

## 최종 PDF 이미지 검수

콘택트 시트만 보지 말고 최종 PDF 크기로 각 이미지를 확인한다.

- 바로 앞뒤 문장이 가리키는 장소·행동·감정과 이미지가 맞는가
- 실사풍·일러스트·SVG의 성격과 출처 표기가 캡션에 보이는가
- 얼굴·손·문서 가장자리·도형이 잘리지 않았는가
- 가짜 글자·깨진 숫자·로고·워터마크·읽을 수 있는 개인정보가 없는가
- 작은 화면에서도 핵심 행동이 보이고, 본문을 가리지 않는가
- 같은 이미지를 서로 다른 의미의 장에서 재사용하지 않았는가

하나라도 실패하면 해당 이미지의 프롬프트·에셋·배치·캡션을 고친 뒤 다시 조판하고, 수정 전 이미지를 최종 폴더에 남기지 않는다.

## 생성 수단

환경에 있는 이미지 생성 수단을 쓴다. Codex 환경이면 `$imagegen`, Claude Code면 사용 가능한 생성 도구 또는 codex-imagegen 스킬. 후보 3컷을 생성해 가장 나은 1컷을 고르고, 3컷 모두 무텍스트 원칙을 어기면 프롬프트를 수정해 재생성한다. 수단이 없으면 벡터 폴백(각 테마의 기본 표지)으로 진행한다 — 아트 없이도 모든 표지는 성립한다.

후보를 고를 때는 예쁜 정도가 아니라 문맥 일치·독자 이해·안전성을 우선한다. 실제 사진을 사용할 경우 내부 기록에는 라이선스와 원출처를 남기되, 독자용 캡션에는 사람이 읽을 수 있는 출처명만 쓴다.
